Aquí encontrarás el control de cambios de la API de Prontopaga, en donde podrás conocer las nuevas funcionalidades, mejoras o correcciones de errores.

Conoce nuestra nomenclatura, los tipos de cambios y el histórico de versiones a continuación.

## Nomenclatura

Utilizamos la norma ISO 8601 (AAAA-MM-DD) para las fechas y el versionado numérico:

* Cambio de **versión 1 a 2** cuando la nueva versión de la API es incompatible con la versión anterior, es decir, cuando los cambios en los endpoints son mayores.
* Cambio de **versión 1.1 a 1.2** cuando los cambios en la API son compatibles con versiones anteriores. Pueden ser nuevas funciones o correcciones de errores, por ejemplo.

## Tipos de cambios

:new: **NEW FEATURE** para nuevas funciones.

:hammer_and_wrench: **IMPROVEMENTS** para cambios en una funcionalidad ya existente.

:white_check_mark: **FIX** para corrección de errores.

:x: **REMOVED** para funciones eliminadas.

:rocket: **BREAKING CHANGE** para cambios mayores en la API, incompatibles con la versión anterior.

:closed_lock_with_key: **SECURITY** para cambios relacionados a seguridad.
